## النموذج التنظيمي

```
Branch (فرع)
   └── Department (قسم)
          └── User (موظف)

Office (مكتب)  ←  مسار مستقل تماماً
   └── User
```

المستخدم إما في **فرع + قسم** أو في **مكتب**. المكتب لا يتبع فرعاً ولا يحوي أقساماً.
مكاتب البذور: الديوان (REGISTRY)، الذاتية (PERSONNEL)، القلم (CLERICAL).

## `OrganizationScopeService` — الخدمة المشتركة

`app/Modules/Organization/Services/OrganizationScopeService.php`

**تُستخدم في أربعة موديولات**: Organization, Employees, Drive, Tasks.

### دوال الاستعلام — ترجع `Builder`

```php
public function employees(User $actor): Builder
{
    return match ($actor->primaryRole()) {
        'general_manager', 'database_manager' => User::query(),
        'branch_manager'  => User::where('branch_id', $actor->branch_id),
        'department_head' => User::where('department_id', $actor->department_id),
        default           => User::whereKey($actor->id),
    };
}

public function branches(User $actor): Builder
{
    return in_array($actor->primaryRole(), ['general_manager', 'database_manager'])
        ? Branch::query()
        : Branch::whereKey($actor->branch_id);
}

public function departments(User $actor): Builder
{
    return match ($actor->primaryRole()) {
        'general_manager', 'database_manager' => Department::query(),
        'branch_manager'  => Department::where('branch_id', $actor->branch_id),
        'department_head' => Department::whereKey($actor->department_id),
        default           => Department::whereRaw('1 = 0'),      // لا شيء
    };
}
```

> `whereRaw('1 = 0')` نمط متكرر: يرجع `Builder` فارغاً لا `null`، فيبقى الكود
> المستهلك موحّداً بلا فحوص إضافية.

### دوال الفحص — ترجع `bool`

| الدالة | القاعدة |
| --- | --- |
| `canManageBranch()` | المدير العام ومدير قواعد البيانات فقط |
| `canManageDepartment()` | هما، أو مدير الفرع لأقسام فرعه |
| `canManageEmployee()` | هما، أو مدير الفرع لموظفي فرعه، أو رئيس القسم لموظفي قسمه |
| `canAssignRole()` | هما لكل الأدوار؛ مدير الفرع محصور بـ`employee`, `technician`, `department_head` |

> `canAssignRole()` يمنع تصعيد الامتيازات: مدير فرع لا يستطيع إنشاء مدير عام.

## نمط التحقق المزدوج

في `OrganizationRepository::updateDepartment()`:

```php
if (! $this->scope->canManageDepartment($actor, $department))
    throw new AuthorizationException(__('messages.organization_forbidden'));

$target = new Department($data + ['branch_id' => $department->branch_id]);
if (! $this->scope->canManageDepartment($actor, $target))
    throw new AuthorizationException(__('messages.organization_forbidden'));

$department->update($data);
```

**فحصان: على الحالة الحالية وعلى الحالة بعد التعديل.**

> **لماذا؟** لو اكتفينا بالأول لاستطاع مدير فرع دمشق نقل قسم من فرعه إلى حلب —
> يملك القسم الآن، لكن لا يملك الوجهة. الفحص الثاني يمنع تسريب سجل خارج النطاق.
> **طبّق هذا النمط في أي تعديل يغيّر انتماء سجل.**

`createDepartment()` يستخدم النمط نفسه: ينشئ كائناً غير محفوظ للفحص قبل الإنشاء.

## `GET /api/organization`

```php
return response()->json([
    'branches'    => BranchResource::collection($this->organization->branches($request->user())),
    'departments' => DepartmentResource::collection($this->organization->departments($request->user())),
]);
```

مع عدّادات محسوبة:

```php
public function branches(User $actor): Collection
{
    return $this->scope->branches($actor)->withCount(['departments'])->get();
}

public function departments(User $actor): Collection
{
    return $this->scope->departments($actor)->with('branch:id,name')->withCount('users')->get();
}
```

`withCount()` يحسب في استعلام واحد بلا N+1.

## وحدة Offices

`OfficeController` **يحقن `CommunicationRepositoryInterface`** لا مستودعاً خاصاً:

```php
public function __construct(private CommunicationRepositoryInterface $communications) {}
public function index(): JsonResponse { return response()->json($this->communications->offices()); }
```

> **سبب تاريخي:** المكاتب أُضيفت أصلاً لخدمة المراسلات الرسمية (الديوان مكتب).
> يعمل لكنه غير نظيف — لو وسّعت المكاتب، انقل منطقها إلى مستودع خاص بها.

المكاتب **بلا نطاق**: `offices.manage` مملوكة للمدير العام ومدير قواعد البيانات فقط،
فمن يملكها يرى الكل.

## قواعد الحذف

| الحذف | الأثر |
| --- | --- |
| فرع | يحذف أقسامه (`cascadeOnDelete`)، ويفرّغ `branch_id` لدى مستخدميه (`nullOnDelete`) |
| قسم | يفرّغ `department_id` لدى مستخدميه، **ويحذف مهامه** (`cascadeOnDelete`) |
| مكتب | يفرّغ `office_id` لدى مستخدميه |

> **حذف قسم يحذف مهامه.** انتبه: لا يوجد حذف ناعم في المشروع. اجعل الواجهة تؤكد
> بوضوح، أو استبدل الحذف بـ`is_active = false`.

## نقاط التوسّع

| ما تريد إضافته | كيف |
| --- | --- |
| مستوى تنظيمي ثالث (شعبة) | جدول جديد + توسيع كل دوال `OrganizationScopeService` |
| حذف ناعم | `softDeletes()` في الترحيلات + `->withTrashed()` حيث يلزم |
| نقل موظف مع سجل | جدول `user_transfers` + خدمة نقل |
| مدير للفرع/القسم بحقل صريح | `manager_id` في `branches`/`departments` بدل الاستنتاج من الدور |
| مكاتب ذات نطاق | مستودع خاص + خدمة نطاق للمكاتب |
