## المصفوفة

```php
public function matrix(): Collection
{
    $permissions = Permission::orderBy('name')->pluck('name');

    return Role::with('permissions')->orderBy('name')->get()->map(fn (Role $role) => [
        'id'   => $role->id,
        'name' => $role->name,
        'permissions' => $role->permissions->pluck('name'),
        'available_permissions' => $permissions,
    ]);
}
```

كل دور يحمل صلاحياته الحالية **وقائمة كل الصلاحيات المتاحة** — الواجهة ترسم
المصفوفة كاملة بلا طلب ثانٍ.

```
                  reports.view  reports.create  employees.view  ...
employee              ✔              ✔               ✗
department_head       ✔              ✗               ✔
branch_manager        ✔              ✗               ✔
```

## المزامنة

```php
public function sync(Role $role, array $permissions): Role
{
    $role->syncPermissions($permissions);
    return $role->load('permissions');
}
```

التحقق:

```php
public function rules(): array
{
    return [
        'permissions'   => ['present', 'array'],
        'permissions.*' => ['string', 'exists:permissions,name'],
    ];
}
```

| القاعدة | السبب |
| --- | --- |
| `present` | **الحقل يجب أن يوجد ولو كان مصفوفة فارغة** — نزع كل الصلاحيات فعل مقصود لا خطأ |
| `exists:permissions,name` | لا يمكن اختراع صلاحية غير معرّفة |
| `syncPermissions` | **يستبدل** القائمة كاملة — ما لا يُرسل يُنزع |

> **`syncPermissions` استبدال لا إضافة.** أرسل القائمة الكاملة دائماً.

### الكاش

`spatie/laravel-permission` يمسح كاشه تلقائياً عند `syncPermissions()`.
لكن عند التعديل **من ترحيل أو بذرة** يجب المسح يدوياً:

```php
app()[\Spatie\Permission\PermissionRegistrar::class]->forgetCachedPermissions();
```

## الأثر على الواجهة

الصلاحيات تصل إلى الواجهة عبر `UserResource`:

```php
'permissions' => $this->getAllPermissions()->pluck('name'),
```

`AppShell.jsx` يبني القائمة الجانبية منها مقابل `json/navigation.json`.

> **التأثير لا يظهر فوراً للمستخدم المتأثر.** الواجهة تحمّل الصلاحيات عند الدخول
> أو `/auth/me`. تغيير صلاحيات دور يتطلب من مستخدميه **إعادة تحميل الصفحة**.
> الخادم يطبّق التغيير فوراً — الواجهة فقط هي المتأخرة.

## إضافة صلاحية — الخطوات الأربع

**1.** `BackEnd/database/seeders/RolePermissionSeeder.php` — أضف الاسم إلى
`$permissions` واربطه بالأدوار في `$roles`.

**2.** ترحيل منح للبيئات القائمة (البذور لا تُعاد على الإنتاج):

```php
$permission = Permission::firstOrCreate(['name' => 'assets.view', 'guard_name' => 'web']);
Role::where('name', 'general_manager')->first()?->givePermissionTo($permission);
app()[\Spatie\Permission\PermissionRegistrar::class]->forgetCachedPermissions();
```

**3.** `FrontEnd/src/i18n/permissionDescriptions.js` — الوصف العربي.

**4.** افرضها في المسار:

```php
Route::get('assets', [AssetController::class, 'index'])->middleware('permission:assets.view');
```

## تحذيرات

| الخطر | التفصيل |
| --- | --- |
| **نزع `roles.permissions.manage`** | إن نزعتها من `database_manager` **يفقد الجميع القدرة على إدارة الصلاحيات**. الإصلاح يتطلب `php artisan db:seed --class=RolePermissionSeeder` أو `tinker`. |
| **إعادة تشغيل البذرة تمسح التخصيصات** | `syncPermissions` في البذرة يستبدل القائمة. أي تعديل من الشاشة سيُفقد. **أضف التعديلات الدائمة إلى `$roles` في البذرة.** |
| **الأدوار غير قابلة للإنشاء من الشاشة** | الأدوار السبعة ثابتة في البذرة والترحيلات. إضافة دور تتطلب بذرة/ترحيلاً وتعديل خدمات النطاق (`match` على `primaryRole()`). |

> **إضافة دور جديد ليست تغييراً في البيانات فقط.** كل خدمات النطاق
> (`OrganizationScopeService`, `ReportAccessService`, …) تستخدم `match` على الدور،
> والفرع `default` هو الأضيق. دور جديد بلا تعديلها = صلاحيات موظف عادي.

## الصلاحيات المباشرة للأشخاص

`model_has_permissions` يسمح بمنح صلاحية لشخص بعينه دون تغيير دوره:

```php
$user->givePermissionTo('hr.view');
```

مستخدم فعلاً: `hr.view` و`hr.manage` تُمنح لمنتسبي قسم الموارد البشرية مباشرةً
لا عبر الأدوار — انظر `2026_07_29_000001_create_hr_module.php`:

```php
public const PERMISSIONS = [
    // تُمنح لمنتسبي قسم الموارد البشرية مباشرةً، لا عبر الأدوار.
    'hr.view' => [],
    'hr.manage' => [],
    'hr.request' => ['database_manager', 'general_manager', /* ... */],
];
```

> **شاشة إدارة الصلاحيات لا تعرض الصلاحيات المباشرة** — تدير الأدوار فقط.
> امنحها بترحيل أو `tinker`.

## نقاط التوسّع

| ما تريد إضافته | كيف |
| --- | --- |
| إدارة الصلاحيات المباشرة للأشخاص | مسار جديد + شاشة + `givePermissionTo()` / `revokePermissionTo()` |
| إنشاء أدوار من الشاشة | مسار + مراجعة كل خدمات النطاق للتعامل مع أدوار غير معروفة |
| تجميع الصلاحيات في فئات | تصنيف بالبادئة (`reports.*`) وعرضها مجموعة |
| سجل تغييرات الصلاحيات | جدول `permission_change_log` |
| نسخ صلاحيات دور إلى آخر | زر في الواجهة يستدعي `sync` بقائمة الدور المصدر |
