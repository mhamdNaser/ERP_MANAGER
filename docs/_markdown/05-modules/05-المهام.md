## `GET /api/tasks` — لوحة قسم واحد

```php
$departments = $this->visibleDepartments($user)->with('branch:id,name')->orderBy('name')->get();
$showAll = $request->boolean('all') && in_array($user->primaryRole(), ['general_manager', 'database_manager']);
$departmentId = $request->integer('department_id') ?: $user->department_id ?: $departments->first()?->id;

abort_unless($showAll || ($departmentId && $departments->contains('id', $departmentId)),
    403, 'لا يمكنك الوصول إلى لوحة هذا القسم.');
```

| المعامل | الأثر |
| --- | --- |
| `?department_id=5` | لوحة قسم محدد — **يجب أن يكون ضمن أقسامه المرئية** |
| `?all=1` | كل الأقسام — **للمدير العام ومدير قواعد البيانات فقط** |
| بلا معامل | قسم المستخدم، أو أول قسم مرئي |

`$departments->contains('id', $departmentId)` يمنع تمرير معرّف قسم خارج النطاق.

### الاستجابة

```json
{
  "departments": [{ "id": 1, "name": "قسم البنية التحتية", "branch": {"id":1,"name":"فرع دمشق"} }],
  "active_department_id": 1,
  "members": [{ "id": 3, "name": "سامر", "job_title": "موظف تقني" }],
  "tasks": [ /* TaskResource */ ]
}
```

`members` = الموظفون النشطون في القسم — لقائمة إسناد المهمة بلا طلب إضافي.

### التحميل المسبق

```php
Task::with([
    'department:id,name', 'creator:id,name', 'assignee:id,name,job_title',
    'files.uploader:id,name,role',
    'activities' => fn ($a) => $a->with('actor:id,name,job_title')->latest(),
])->orderBy('position')->orderByDesc('created_at')->get();
```

كل ما تحتاجه البطاقة في استعلام واحد. لاحظ تحديد الأعمدة (`:id,name`) —
يقلّل حجم النقل.

## التصفية والبحث في اللوحة — واجهة فقط

`GET /api/tasks` يعيد **اللوحة كاملة** في استجابة واحدة: كل مهام القسم (أو كل
الأقسام مع `?all=1`) ومعها `members` و`departments`. لذلك تجري التصفية والبحث
**داخل المتصفح بلا أي طلب إضافي** — لا معاملات استعلام ولا تعديل على الخادم.
إضافة بُعد تصفية جديد لا تحتاج إلى الباك أند ما دام الحقل موجوداً في
`TaskResource`.

| الملف | الدور |
| --- | --- |
| `components/taskFiltering.js` | المنطق: `filterTasks()` · `buildFilterOptions()` · `countActiveFilters()` |
| `components/TaskFilters.jsx` | الواجهة: شريط الحقول فوق الأعمدة |
| `components/taskUtils.js` | `normalizeText()` · `toDateKey()` · `shiftDateKey()` · `isOverdue()` |

### أبعاد التصفية

| البعد | القيم | المصدر |
| --- | --- | --- |
| المكلّف | موظف محدد · `unassigned` | `members` + كل `assignee` على اللوحة |
| الأولوية | `low` · `medium` · `high` · `urgent` | `priorityLabels` في `taskMeta.jsx` |
| الاستحقاق | `overdue` · `today` · `week` · `none` | محسوب من `due_date` |
| التصنيف | أي `label` موجود · `__none__` | مشتق من مهام اللوحة |
| المنشئ | أي `creator` | مشتق — يظهر الحقل فقط عند وجود أكثر من منشئ |
| المرفقات | `with` · `without` | `files.length` |

> **قائمة المكلّفين اتحاد لا نسخة.** تُبنى من `members` **و**من المكلّفين
> الموجودين فعلاً على اللوحة. الموظف الذي عُطّل حسابه أو نُقل من القسم يبقى
> مسنَداً إلى مهامه، ولولا الاتحاد لصارت تلك المهام غير قابلة للوصول من الفلتر.

### البحث

حقل البحث الواحد يغطي: العنوان، الوصف، التصنيف، **اسم المكلّف ومسمّاه الوظيفي**،
اسم المنشئ، واسم القسم.

```js
const terms = normalizeText(search).split(" ").filter(Boolean);
return terms.every((term) => haystack.includes(term));
```

| القاعدة | الأثر |
| --- | --- |
| تطبيع عربي | `normalizeText()` يحذف التشكيل والتطويل ويوحّد `أإآ←ا` و`ى←ي` و`ة←ه` — فيطابق البحث عن `احمد` موظفاً مخزّناً باسم `أحمد` |
| كل الكلمات معاً | `every` لا `some` — `احمد صيانة` يعطي مهام الصيانة المسندة لأحمد وحدها |
| بلا حساسية لحالة الأحرف | `toLowerCase()` داخل التطبيع — يفيد الأسماء اللاتينية |

### قواعد ثبّتها هذه الميزة

> **`due_date` نص لا تاريخ.** يصل بصيغة `YYYY-MM-DD`، ومقارنته عبر
> `new Date(due_date) < new Date()` تَعُدّ مهمةً تستحق **اليوم** متأخرةً بمجرد
> تجاوز منتصف ليل UTC. لذلك يقارن `isOverdue()` مفاتيح نصية من `toDateKey()`،
> وتستدعيه بطاقةُ المهمة وفلترُ «متأخرة» معاً حتى لا تناقض الشارةُ الحمراء الفلترَ.

> **لا تسمِّ مكوّناً وملفَ منطق بالاسم نفسه مع اختلاف حالة الأحرف فقط.** نظام
> ملفات ويندوز غير حسّاس لحالة الأحرف، فاستيراد `./components/TaskFilters` بلا
> لاحقة يطابق أيضاً `taskFilters.js` ويفشل بناء Vite بـ`MISSING_EXPORT`.
> لهذا سُمّي ملف المنطق `taskFiltering.js`.

- **المؤشرات تتبع المصفّى.** `TaskBoardStats` يستقبل القائمة بعد التصفية، فلا
  يعرض إجمالياً يناقض الأعمدة تحته. `completion` يُحسب من المصفّى كذلك.
- **تبديل القسم يصفّر الفلاتر.** معرّفات المكلّفين والتصنيفات والمنشئين مرتبطة
  بالقسم، وحملها إلى لوحة أخرى يُفرغ الشاشة بلا سبب ظاهر للمستخدم.

## الإنشاء — حساب الموضع

```php
$position = (Task::where('department_id', $department->id)
    ->where('status', $data['status'] ?? 'planned')->max('position') ?? -1) + 1;
```

المهمة الجديدة تذهب إلى **آخر العمود**. `?? -1` يجعل أول مهمة في الموضع 0.

## التعديل — رصد التغييرات

```php
$before = $task->only(['title','description','assignee_id','priority','label','due_date','status']);
$task->update($data);

$changes = collect($task->only(array_keys($before)))
    ->filter(fn ($value, $key) => (string) ($before[$key] ?? '') !== (string) ($value ?? ''))
    ->mapWithKeys(fn ($value, $key) => [$key => ['before' => $before[$key] ?? null, 'after' => $value]])
    ->all();

if ($changes)
    $this->activities->record($task, $request->user(), 'task_updated', 'عدّل بيانات المهمة.', ['changes' => $changes]);
```

| النقطة | التفصيل |
| --- | --- |
| لقطة قبل التحديث | `$before` |
| مقارنة نصية | `(string)` يتجنّب فروق الأنواع الزائفة (`1` مقابل `"1"`) |
| `if ($changes)` | **لا يُسجَّل شيء إن لم يتغير شيء** — لا ضجيج في السجل |
| الشكل | `['assignee_id' => ['before' => 3, 'after' => 5]]` في عمود `details` (JSON) |

## النقل

```php
$task->update([
    'status'       => $data['status'],
    'position'     => $data['position'] ?? 0,
    'completed_at' => $data['status'] === 'completed' ? now() : null,
]);

if ($previousStatus !== $task->status)
    $this->activities->record($task, $user, 'task_moved', 'نقل المهمة إلى حالة جديدة.',
        ['from_status' => $previousStatus, 'to_status' => $task->status]);
```

> `completed_at` يُضبط عند الاكتمال و**يُفرَّغ عند الخروج منه**. لهذا يعمل مخطط
> `task_trend` في لوحة المعلومات بدقة.
> إعادة الترتيب داخل العمود نفسه لا تُسجَّل — ضجيج بلا فائدة.

## سجل الحركات

`TaskActivityService::record()`:

```php
return TaskActivity::create([
    'task_id'       => $task->id,
    'department_id' => $task->department_id,   // ★ مكرّر عمداً
    'actor_id'      => $actor->id,
    'action'        => $action,
    'task_title'    => $task->title,           // ★ مكرّر عمداً
    'summary'       => $summary,
    'details'       => $details ?: null,
]);
```

> **`task_title` و`department_id` مكرّران عمداً.** الصلاحية
> `tasks.delete_with_activities` تسمح بحذف المهمة، وحينها يبقى السجل قابلاً للقراءة
> لأنه لا يعتمد على السجل المحذوف.

### الأفعال المسجّلة

| الفعل | متى | من يسجّله |
| --- | --- | --- |
| `task_created` | إنشاء | `TaskController::store()` |
| `task_updated` | تعديل بتغيير فعلي | `TaskController::update()` |
| `task_moved` | تغيير الحالة | `TaskController::move()` |
| `file_attached` | إرفاق ملف بمهمة | **`DriveController::store()`** |

> `DriveController` يستدعي `TaskActivityService` مباشرةً — الخدمة مشتركة بين موديولين.

`GET /api/task-activities` يقبل فلاتر عبر معاملات الاستعلام، وتُنظَّف الفارغة في
`api.js` قبل الإرسال.

## النطاق

`visibleDepartments()` يستخدم `OrganizationScopeService::departments()`:

| الدور | يرى لوحات |
| --- | --- |
| `general_manager` / `database_manager` | كل الأقسام + `?all=1` |
| `branch_manager` | أقسام فرعه |
| `department_head` | قسمه |

يُظهر للموظف ما أُسند إليه **أو** ما أنشأه.
