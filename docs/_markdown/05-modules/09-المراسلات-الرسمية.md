## الاتجاهات وقواعد الأطراف

`FormalPartyResolver::DIRECTION_RULES`:

| الاتجاه | الجهة المصدرة | الجهة المخاطبة |
| --- | --- | --- |
| `external_to_internal` | `external_entity` | `our_org` |
| `internal_to_external` | `branch`, `department`, `office`, `general_manager`, `diwan` | `external_entity` |
| `internal_to_internal` | نفس القائمة الداخلية | نفس القائمة الداخلية |

> إلى `external_to_internal`.

### أنواع الأطراف

```php
public const INTERNAL_TYPES = ['branch', 'department', 'office', 'general_manager', 'diwan'];
public const OUR_ORG_LABEL = 'مؤسستنا';
```

`resolve($type, $id, $fallback)` يحوّل (نوع، معرّف) إلى تسمية عربية موحّدة:

| النوع | التسمية |
| --- | --- |
| `our_org` | "مؤسستنا" |
| `diwan` | "الديوان" |
| `general_manager` | اسم المدير أو "المدير العام" |
| `branch` / `department` / `office` | اسم الجهة من قاعدة البيانات |
| `external_entity` | اسم الجهة الخارجية |
| `user` | اسم المستخدم |

> **نمط متعدد الأشكال:** `source_type` + `source_id` + `source_label`.
> النص المخزَّن (`*_label`) يبقى صحيحاً حتى لو حُذفت الجهة لاحقاً.

## الديوان — الدور المحوري

```php
public function isDiwanUser(?User $user): bool
{
    $office = $user->relationLoaded('office') ? $user->office : $user->office()->first(['code', 'name']);

    return $office?->code === 'REGISTRY'
        || (is_string($office?->name) && str($office->name)->contains(['ديوان', 'السجل', 'registry']));
}

/** الديوان وحده يرى كامل السلسلة بحكم مسؤوليته عن التسجيل والتوجيه. */
public function canViewFullThread(?User $user): bool { return $this->isDiwanUser($user); }

public function canCreate(?User $user): bool
{
    return $user && ($user->role === 'database_manager' || $this->isDiwanUser($user));
}
```

| الصلاحية | من يملكها |
| --- | --- |
| رؤية السلسلة كاملة | الديوان فقط |
| إنشاء مراسلة | الديوان + مدير قواعد البيانات |

> **الديوان يُكتشف بالرمز `REGISTRY` أو باسم يحوي "ديوان"/"السجل"/"registry".**
> عند نقل النظام لمؤسسة أخرى راجع هذا الثابت.

## نموذج الرؤية التسلسلية

**أذكى جزء في الوحدة.** القاعدة الموثّقة في رأس الخدمة:

> "لا ترى الجهة إلا المعالجات التي وصلت إليها أو صدرت عنها."

### الخطوة 1 — أي محطة تخصّني؟

```php
public function eventVisibleTo(FormalCorrespondenceEvent $event, User $user): bool
{
    if ((int) $event->actor_id === (int) $user->id) return true;                       // أنا من أنشأها
    if ($event->assigned_user_id && (int) $event->assigned_user_id === (int) $user->id) return true;  // أُحيلت إليّ

    return $this->partyMatchesUser($event->target_type, $event->target_id, $user)      // موجّهة لجهتي
        || $this->partyMatchesUser($event->source_type, $event->source_id, $user);     // صادرة عن جهتي
}
```

`partyMatchesUser()` يقارن نوع الجهة بانتماء المستخدم:

```php
return match ($type) {
    'diwan'           => الديوان,
    'general_manager' => $user->role === 'general_manager',
    'branch'          => $id === (int) $user->branch_id,
    'department'      => $id === (int) $user->department_id,
    'office'          => $id === (int) $user->office_id,
    'user'            => $id === (int) $user->id,
    default           => false,
};
```

### الخطوة 2 — كل ما سبق وصولي

```php
$orderedEvents = $correspondence->events
    ->sortBy(fn ($e) => sprintf('%020d-%020d', $e->created_at?->getTimestamp() ?? 0, $e->id))
    ->values();

$accessibleIndexes = $orderedEvents->keys()
    ->filter(fn (int $i) => $this->eventVisibleTo($orderedEvents[$i], $user));
$lastAccessibleIndex = $accessibleIndexes->isEmpty() ? null : $accessibleIndexes->max();

// عند وصول المراسلة إلى الجهة أو الموظف، تظهر له المعالجات السابقة حتى نقطة وصولها.
$visibleEvents = $lastAccessibleIndex === null
    ? $orderedEvents->take(0)
    : $orderedEvents->take($lastAccessibleIndex + 1)->values();
```

> **المنطق:** يجد **آخر** محطة تخصّك، ثم يُظهر كل ما قبلها.
> فترى سياق وصول المراسلة إليك — لكن **لا ترى ما جرى بعدك**.

مثال: مراسلة مرّت بالديوان ← المدير العام ← قسمك ← قسم آخر.
أنت في القسم الثالث ← ترى المحطات الثلاث الأولى ولا ترى الرابعة.

`sprintf('%020d-%020d', timestamp, id)` يضمن ترتيباً مستقراً حتى للمحطات المتزامنة.

### الخطوة 3 — الوثائق تتبع المحطات

```php
$correspondence->setRelation('documents',
    $correspondence->documents
        ->filter(fn ($doc) => in_array($doc->formal_correspondence_event_id, $visibleEventIds, true))
        ->values()
);
```

### الخطوة 4 — صلاحيات التحرير مرفقة بالاستجابة

`attachEditPermissions()` يضيف `can_edit` على المراسلة وعلى كل محطة ووثيقة، فتعرف
الواجهة ماذا تُظهر بلا منطق مكرّر.

> **الفلترة في PHP لا في SQL** — لأن المنطق تسلسلي ويعتمد على الترتيب.
> مقبول لأن عدد المحطات في المراسلة الواحدة محدود، لكنه سبب وجيه لعدم استخدام
> هذا النمط على جداول كبيرة.

### الربط بلوحة المهام

```php

                               User $assignee, User $assigner): ?Task
```

إحالة محطة إلى موظف **تنشئ مهمة حقيقية** في لوحة قسمه، ويُحفظ `task_id` في المحطة.
تكامل عملي: المراسلة الواردة تتحول إلى عمل ملموس متتبَّع.

### تحديد الموقّع

رئيس القسم للقسم، مدير الفرع للفرع، المدير العام… ثم يُدرج توقيعه في الكتاب المولّد.

## دورة المعالجة

```
إنشاء المراسلة (الديوان)
      │
      ▼
محطة: من جهة ← إلى جهة
      │
      ├─ decision   قرار على المحطة (POST .../decision)
      ├─ response   رد أو توصية (POST .../response)
      ├─ assign     إحالة لشخص + إنشاء مهمة (POST .../assign)
      └─ documents  إضافة وثيقة (POST .../documents)
      │
      ▼
محطة تالية … وهكذا حتى الإغلاق
```

`action_required` يحدد المطلوب من الجهة، و`defaultActionRequired($targetType)`
يقترحه تلقائياً حسب نوع الجهة المخاطبة.
