# قاعدة البيانات — الاتصالات والإعداد

## المحرّك

| البيئة | المحرّك | السبب |
| --- | --- | --- |
| الإنتاج | PostgreSQL | الافتراضي في `.env.example` |
| التطوير | PostgreSQL (أو SQLite مؤقتاً) | حسب توفّر الخادم |
| الاختبارات | SQLite في الذاكرة | سرعة وعزل — `phpunit.xml` |

> **pgAdmin ليس خادم قاعدة بيانات.** هو واجهة إدارة فقط. يجب تثبيت
> PostgreSQL Server منفصلاً وتشغيله على `127.0.0.1:5432`.

> `config/database.php` يجعل الاتصال الافتراضي `sqlite` إن لم يُضبط `DB_CONNECTION`.
> تأكد من ضبطه على `pgsql` في `.env`.

## الاتصالات الثلاثة

`BackEnd/config/database.php`:

| الاتصال | المستخدم | الصلاحيات | الاستخدام |
| --- | --- | --- | --- |
| `pgsql` | `cnd_app` | SELECT, INSERT, UPDATE, DELETE, CREATE | **الافتراضي** — كل عمليات التطبيق والترحيلات |
| `pgsql_owner` | `cnd_owner` | مالك المخطط | النسخ الاحتياطي والعمليات الإدارية |
| `pgsql_readonly` | `cnd_readonly` | SELECT فقط | التقارير والتصدير وأدوات خارجية |

الإعدادات المشتركة:

```php
'charset'        => 'utf8',
'prefix'         => '',
'prefix_indexes' => true,
'search_path'    => 'public',
'sslmode'        => env('DB_SSLMODE', 'prefer'),
```

### الاستخدام في الشيفرة

```php
DB::connection('pgsql_readonly')->table('reports')->get();
Model::on('pgsql_owner')->get();
```

> عملياً كل الشيفرة تستخدم الاتصال الافتراضي. الاتصالان الآخران بنية جاهزة
> لفصل الأحمال لاحقاً — مثل توجيه التقارير الثقيلة إلى نسخة قراءة.

## التهيئة — `BackEnd/scripts/postgres-provision.sql`

```powershell
psql -U postgres -f scripts/postgres-provision.sql
```

### ما ينشئه

```sql
CREATE ROLE cnd_owner    LOGIN PASSWORD 'CndOwner?2026';
CREATE ROLE cnd_app      LOGIN PASSWORD 'CndApp?2026';
CREATE ROLE cnd_readonly LOGIN PASSWORD 'CndRead?2026';

CREATE DATABASE cnd_manager OWNER cnd_owner ENCODING 'UTF8';
```

> **غيّر كلمات المرور** قبل التشغيل على أي خادم حقيقي، واجعلها تطابق `.env`.

### توزيع الصلاحيات

```sql
GRANT CONNECT ON DATABASE cnd_manager TO cnd_app, cnd_readonly;
GRANT USAGE, CREATE ON SCHEMA public TO cnd_owner;
GRANT USAGE ON SCHEMA public TO cnd_app, cnd_readonly;

-- Laravel ينفّذ الترحيلات بحساب cnd_app، فيحتاج إنشاء الكائنات
GRANT CREATE ON SCHEMA public TO cnd_app;

ALTER DEFAULT PRIVILEGES FOR ROLE cnd_owner IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO cnd_app;
ALTER DEFAULT PRIVILEGES FOR ROLE cnd_owner IN SCHEMA public
  GRANT SELECT ON TABLES TO cnd_readonly;
ALTER DEFAULT PRIVILEGES FOR ROLE cnd_app IN SCHEMA public
  GRANT SELECT ON TABLES TO cnd_readonly;
```

> **`ALTER DEFAULT PRIVILEGES` مهم:** يضمن أن أي جدول يُنشأ **مستقبلاً** يحصل على
> الصلاحيات تلقائياً. بدونه سيفقد `cnd_readonly` الوصول إلى كل جدول جديد يضيفه ترحيل.

`ENCODING 'UTF8'` إلزامي — قاعدة تخزّن نصوصاً عربية.

## الترتيب الكامل للتهيئة

```powershell
# 1. تهيئة القاعدة والمستخدمين
psql -U postgres -f BackEnd/scripts/postgres-provision.sql

# 2. ضبط .env
#    DB_CONNECTION=pgsql
#    DB_DATABASE=cnd_manager
#    DB_USERNAME=cnd_app
#    DB_PASSWORD=...

# 3. الترحيلات والبذور
cd BackEnd
php artisan migrate --seed

# 4. الرابط الرمزي للتخزين
php artisan storage:link
```

## الاختلافات بين PostgreSQL و SQLite

الاختبارات تعمل على SQLite بينما الإنتاج PostgreSQL. الفروق التي تسبب مفاجآت:

| الجانب | PostgreSQL | SQLite |
| --- | --- | --- |
| المفاتيح الأجنبية | مفروضة دائماً | تحتاج تفعيلاً |
| حساسية `LIKE` لحالة الأحرف | حسّاس (`ILIKE` غير حسّاس) | غير حسّاس |
| أنواع البيانات | صارمة | مرنة |
| `JSON` | `json` / `jsonb` أصليان | نص |
| `ALTER TABLE` | كامل | محدود |

> **القاعدة:** لا تكتب SQL خاماً خاصاً بمحرّك. استخدم Eloquent وباني الاستعلامات،
> فيولّد Laravel الصيغة الصحيحة لكل محرّك.

مثال على كتابة محايدة موجودة في المشروع —
`Modules/Hr/Services/HrAccessService.php`:

```php
$query->where('code', 'HR');
foreach (self::HR_KEYWORDS as $keyword) {
    $query->orWhere('name', 'like', "%{$keyword}%");
}
```

`like` تعمل في المحرّكين. `ilike` كانت ستكسر SQLite.

## النسخ الاحتياطي

`Modules/Database/Services/DatabaseBackupService.php` — نوعان:

| النوع | الوصف |
| --- | --- |
| `internal` | نسخة داخل النظام تُحفظ في `storage/app/private/backups/` |
| `external` | نسخة تُنزَّل مباشرةً للمستخدم |

التفاصيل في `05-modules/13-النسخ-الاحتياطي.md`.

### النسخ اليدوي

```powershell
# نسخة كاملة
pg_dump -U cnd_owner -d cnd_manager -F c -f backup.dump

# استعادة
pg_restore -U cnd_owner -d cnd_manager -c backup.dump

# نسخة نصية (قابلة للقراءة)
pg_dump -U cnd_owner -d cnd_manager -f backup.sql
```

> استخدم `cnd_owner` للنسخ لا `cnd_app` — المالك يملك وصولاً كاملاً لكل الكائنات.

## التكامل مع QGIS

المشروع يحوي `docs/attachments/qgis_postgres.sql` و`docs/attachments/QGIS_PostgreSQL.docx`
من مرحلة سابقة — إعداد اتصال QGIS بـPostgreSQL.

الاتصال `pgsql_readonly` مناسب تماماً لهذا: أدوات خارجية تقرأ ولا تكتب.
استخدم بيانات `cnd_readonly` عند ربط QGIS أو أي أداة تحليل.

## مشاكل شائعة

| العَرَض | السبب | الحل |
| --- | --- | --- |
| `could not connect to server` | الخادم متوقف | شغّل خدمة PostgreSQL |
| `password authentication failed` | كلمة مرور غير مطابقة | وحّد `.env` مع سكربت التهيئة |
| `permission denied for schema public` | صلاحيات ناقصة | نفّذ `GRANT CREATE ON SCHEMA public TO cnd_app` |
| `database does not exist` | لم يُنفَّذ سكربت التهيئة | نفّذه |
| نص عربي مشوّه | ترميز غير UTF8 | أعد إنشاء القاعدة بـ`ENCODING 'UTF8'` |
| جدول جديد لا يراه `cnd_readonly` | `ALTER DEFAULT PRIVILEGES` غير مضبوط | نفّذ الأمر أو امنح الصلاحية يدوياً |
| اختبار ينجح والإنتاج يفشل | فرق SQLite/PostgreSQL | تجنّب SQL خاصاً بمحرّك |
