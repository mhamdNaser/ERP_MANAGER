# إدارة الإصدارات والاستعادة

كيف تحفظ نسخة صالحة من النظام، وكيف تعود إليها خلال دقيقتين إذا ظهر خلل في الإصدار الحالي.

الأداة: `scripts/version.ps1` — سكربت PowerShell يعمل على الجهاز المحلي، لا يحتاج إنترنت
ولا خادماً، ولا يرفع شيئاً إلى GitHub.

---

## المبدأ

**إصدار واحد = كود + قاعدة بيانات.** الكود وحده لا يكفي: الترحيلات (migrations) تغيّر
بنية الجداول، فإذا أعدتَ الكود إلى ما قبل ترحيلٍ نُفِّذ فعلاً، بقيت القاعدة ببنية
لا يفهمها الكود القديم — أعمدة زائدة، وجداول لا يعرفها، وبيانات نُقلت إلى مكان آخر.
لذلك يحفظ السكربت الاثنين معاً، ويعيدهما معاً.

**التاريخ يمضي إلى الأمام.** الاستعادة لا تحذف كوميتات ولا تُزيح مؤشر الفرع؛ تُسجَّل
ككوميت جديد فوق `main` محتواه محتوى الإصدار القديم. أي شيء عملته بعد الإصدار يبقى
في التاريخ، ويمكن الرجوع إليه أو استرجاع جزء منه لاحقاً.

---

## ما الذي يتكوّن منه الإصدار

| المكوّن | الموضع | يُرفع إلى Git؟ |
| --- | --- | --- |
| وسم الإصدار | `git tag -a v1.0.0` | نعم |
| رقم الإصدار الحالي | `VERSION` | نعم |
| وصف التغييرات | `CHANGELOG.md` | نعم |
| وثيقة الإصدار | `docs/_markdown/08-releases/v1.0.0.md` | نعم |
| نسخة قاعدة البيانات | `.versions/v1.0.0/db.dump` | **لا** (مُستثنى في `.gitignore`) |
| بطاقة الإصدار | `.versions/v1.0.0/meta.json` | **لا** |

`.versions/` محلي عمداً: نسخ القاعدة ثقيلة، وتحتوي بيانات فعلية لا مكان لها في مستودع كود.
إن أردت نقل إصدار إلى جهاز آخر، انسخ مجلد `.versions/<الوسم>/` يدوياً مع المستودع.

---

## الأوامر

```powershell
.\scripts\version.ps1 status       # أين نحن الآن
.\scripts\version.ps1 list         # كل الإصدارات المحفوظة
.\scripts\version.ps1 save 1.1.0 -Message "وصف الإصدار"
.\scripts\version.ps1 restore 1.0.0
.\scripts\version.ps1 snapshot     # لقطة قاعدة بيانات سريعة بلا وسم
```

> السكربت يقرأ بيانات الاتصال من `BackEnd/.env` (‏`DB_HOST`, `DB_PORT`, `DB_DATABASE`,
> `DB_USERNAME`, `DB_PASSWORD`)، ويبحث عن `pg_dump` و`pg_restore` في `PATH` ثم في
> `C:\Program Files\PostgreSQL\<الإصدار>\bin`.

## حفظ إصدار جديد

```powershell
# 1) راجع ما ستحفظه
.\scripts\version.ps1 status

# 2) احفظ التعديلات بكوميتات واضحة أولاً (مستحسن)
git add -A
git commit -m "feat(fleet): شاشة تقارير الآليات"

# 3) وسّم الإصدار
.\scripts\version.ps1 save 1.1.0 -Message "تقارير فرع الآليات"
```

ماذا يحدث بالترتيب:

```
[1] فحص نظافة شجرة العمل   ← يرفض إن وُجدت تعديلات غير محفوظة
[2] تحديث ملف VERSION       ← كوميت: chore(release): v1.1.0
[3] إنشاء وسم موقَّع         ← git tag -a v1.1.0 -m "..."
[4] نسخ قاعدة البيانات      ← .versions/v1.1.0/db.dump
[5] كتابة بطاقة الإصدار     ← .versions/v1.1.0/meta.json
```

إن كانت لديك تعديلات غير محفوظة وأردت ضمّها في كوميت الإصدار مباشرة:

```powershell
.\scripts\version.ps1 save 1.1.0 -Message "تقارير فرع الآليات" -CommitAll
```

بعد الحفظ **اكتب ما تغيّر في `CHANGELOG.md`**؛ السكربت لا يكتبه عنك لأن وصف التغيير
قرار بشري لا يُستخرج من الكوميتات.

## الاستعادة عند ظهور خلل

```powershell
.\scripts\version.ps1 list          # اختر الإصدار السليم
.\scripts\version.ps1 restore 1.0.0
```

ماذا يحدث بالترتيب:

```
[1] تأكيد منك                       ← يعرض النطاق ثم يسأل y/N
[2] وسم أمان للحالة الحالية          ← safety/pre-restore-<الوقت>
[3] نسخة من القاعدة الحالية          ← .versions/_pre-restore/<الوقت>/db.dump
[4] حفظ التعديلات المعلّقة في stash
[5] إعادة ملفات الكود إلى محتوى الوسم ← وحذف ما أُضيف بعده
[6] كوميت: rollback: العودة إلى v1.0.0
[7] إعادة قاعدة البيانات من db.dump  ← pg_restore --clean --if-exists
```

الخطوتان [2] و[3] هما شبكة الأمان: حتى لو استعدتَ الإصدار الخطأ، الحالة التي كنت
عليها محفوظة بالكامل — كوداً وقاعدةً — ويمكن العودة إليها.

### بعد الاستعادة

```powershell
cd BackEnd;  composer install
cd ..\FrontEnd;  npm install
cd ..\BackEnd;  php artisan optimize:clear
```

الاعتماديات لا تعود تلقائياً: `composer.lock` و`package-lock.json` عادا إلى نسختهما
القديمة، لكن مجلدي `vendor/` و`node_modules/` لا يتتبعهما Git فبقيا على حالهما.

تحقّق أن الترحيلات مطابقة لما يتوقعه الكود:

```powershell
php artisan migrate:status
```

يجب ألّا يظهر أي ترحيل بحالة `Pending` لم يكن موجوداً في الإصدار المُستعاد.

## استعادات جزئية

| الحالة | الأمر |
| --- | --- |
| الخلل في الكود فقط، والبيانات الجديدة تهمّك | `restore 1.0.0 -CodeOnly` |
| الكود سليم، لكن بيانات القاعدة فسدت | `restore 1.0.0 -DbOnly` |
| تريد فحص الإصدار القديم دون تطبيقه | `restore 1.0.0 -AsBranch` |

`-AsBranch` ينقلك إلى فرع `restore/v1.0.0-<الوقت>` للفحص، ولا يمسّ `main` إطلاقاً.
للعودة: `git switch main`.

> **تنبيه على `-CodeOnly`:** إن كانت ترحيلات جديدة قد نُفِّذت بعد الإصدار المُستعاد،
> فستبقى آثارها في القاعدة والكود القديم لا يعرفها. استعمله فقط حين تكون واثقاً
> أن الفرق بين الإصدارين لا يمسّ بنية القاعدة.

## لقطة سريعة قبل عمل خطر

قبل تشغيل ترحيل كبير أو `db:seed` أو تجربة تعديل واسع:

```powershell
.\scripts\version.ps1 snapshot
```

ينسخ القاعدة إلى `.versions/_snapshots/<الوقت>/` بلا وسم ولا كوميت. لاستعادتها يدوياً:

```powershell
$env:PGPASSWORD = "<كلمة المرور>"
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" `
    --host=127.0.0.1 --username=postgres --dbname=cnd_manager `
    --clean --if-exists --no-owner --no-privileges `
    ".versions\_snapshots\<الوقت>\db.dump"
```

## الاستعادة يدوياً بلا السكربت

إن تعطّل السكربت لأي سبب، هذه هي الأوامر نفسها:

```powershell
# 1) احفظ الحالة الحالية
git tag -a safety/manual-$(Get-Date -Format yyyyMMdd-HHmmss) -m "قبل الاستعادة"

# 2) أعد الكود إلى الوسم
git restore --source v1.0.0 --staged --worktree -- .
git diff --name-only --diff-filter=A v1.0.0..HEAD   # الملفات المضافة بعده
git rm -f --ignore-unmatch -- <الملفات التي ظهرت أعلاه>
git add -A
git commit -m "rollback: العودة إلى الإصدار v1.0.0"

# 3) أعد القاعدة
$env:PGPASSWORD = "<كلمة المرور>"
& "C:\Program Files\PostgreSQL\18\bin\pg_restore.exe" `
    --host=127.0.0.1 --username=postgres --dbname=cnd_manager `
    --clean --if-exists --no-owner --no-privileges ".versions\v1.0.0\db.dump"
```

## ما لا يُستعمل ولماذا

| الأمر | لماذا لا |
| --- | --- |
| `git reset --hard <وسم>` | يُزيح مؤشر الفرع للخلف، فتختفي الكوميتات التي بعده من الفرع. الاستعادة هنا تُسجَّل ككوميت جديد بدل ذلك |
| `git checkout <وسم>` وحده | يضعك في حالة HEAD منفصل؛ أي كوميت تكتبه بعده معلّق بلا فرع |
| `git push --force` | لا مبرر له في مسار يمضي إلى الأمام دائماً |
| حذف وسم إصدار | الوسم هو المرجع الوحيد لنسخة القاعدة المقابلة في `.versions/` |

## التنظيف الدوري

مجلد `.versions/` ينمو مع كل إصدار واستعادة. راجعه كل بضعة أشهر:

```powershell
Get-ChildItem .versions -Recurse -Filter db.dump |
    Select-Object @{n='المسار';e={$_.Directory.Name}}, @{n='ميغابايت';e={[math]::Round($_.Length/1MB,2)}}, LastWriteTime |
    Sort-Object LastWriteTime
```

احذف ما لم تعد تحتاجه من `_snapshots` و`_pre-restore` — **لا تحذف** مجلدات الإصدارات
الموسومة (`v*`) التي قد تعود إليها.

وسوم الأمان المتراكمة:

```powershell
git tag -l "safety/*"
git tag -d safety/pre-restore-20260922-101500
```

## المشاكل الشائعة

| العرَض | السبب | الحل |
| --- | --- | --- |
| `لم يُعثر على pg_dump` | أدوات عميل PostgreSQL غير مثبّتة أو خارج `PATH` | ثبّت PostgreSQL، أو احفظ الإصدار بـ `-NoDb` ووثّق ذلك |
| `pg_restore انتهى بالرمز 1` | تحذيرات إسقاط لكائنات غير موجودة | طبيعي غالباً؛ تحقّق من البيانات بـ `php artisan migrate:status` واستعلام سريع |
| `الوسم v1.1.0 موجود مسبقاً` | الرقم مستعمل | ارفع الرقم، أو `git tag -d v1.1.0` إن كان وسماً خاطئاً لم يُشارَك |
| `هناك N ملف غير محفوظ` | شجرة العمل غير نظيفة عند `save` | احفظها بكوميت، أو أضف `-CommitAll` |
| الشاشة تعرض رموزاً مشوّهة | ملف السكربت فقد ترويسة BOM | أعد حفظه بترميز UTF-8 **with BOM** |
