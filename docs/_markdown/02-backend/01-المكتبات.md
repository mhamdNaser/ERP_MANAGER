### ملاحظة على تثبيت إصدار spatie

`spatie/laravel-permission` مثبّت على `6.21` بلا `^`. هذا مقصود: المشروع يعتمد على
بنية جداول الصلاحيات مباشرة في الترحيلات (مثل
`2026_06_19_000004_grant_registry_formal_correspondence_permissions.php` التي تستدعي
`Permission::firstOrCreate` و`Role::givePermissionTo`)، وتغيير إصدار رئيسي قد يكسرها.
لا ترفع الإصدار دون مراجعة كل ترحيلات المنح.

### ما تقدّمه spatie فعلياً

| العنصر | الاستخدام |
| --- | --- |
| `HasRoles` trait | مضاف إلى `app/Models/User.php` |
| `permission:` middleware | مسجّل في `bootstrap/app.php`، مستخدم في كل مسار تقريباً |
| `role:` middleware | مسجّل لكن نادر الاستخدام — المشروع يفضّل الصلاحيات |
| `role_or_permission:` | مسجّل، غير مستخدم حالياً |
| `PermissionRegistrar` | يُستخدم لمسح كاش الصلاحيات بعد التعديل |

صيغة "أو" مدعومة بالخط العمودي:

```php
->middleware('permission:messages.view|correspondences.view')
```

يكفي أن يملك المستخدم إحداهما. هذه الصيغة موجودة في
`Modules/Communications/Routes/api.php` للتوافق مع الأسماء القديمة قبل إعادة التسمية.

## سكربتات Composer

معرّفة في `BackEnd/composer.json`:

| الأمر | ما يفعله |
| --- | --- |
| `composer setup` | `install` + إنشاء `.env` + `key:generate` + `migrate` + `npm install` + `npm run build` |
| `composer dev` | يشغّل معاً: `artisan serve` + `queue:listen` + `npm run dev` عبر `concurrently` |
| `composer test` | `config:clear` ثم `artisan test` |

`composer dev` مفيد للتطوير السريع لكنه لا يشغّل Reverb — شغّله يدوياً في نافذة منفصلة.
