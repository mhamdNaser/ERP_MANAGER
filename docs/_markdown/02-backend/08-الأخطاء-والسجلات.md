# الأخطاء والسجلات

## معالج الاستثناءات — `BackEnd/bootstrap/app.php`

```php
->withExceptions(function (Exceptions $exceptions): void {
    $exceptions->render(function (\Throwable $exception, Request $request) {
        if (! $request->expectsJson()
            || $exception instanceof HttpExceptionInterface
            || $exception instanceof HttpResponseException
            || $exception instanceof AuthenticationException
            || $exception instanceof ValidationException) {
            return null;                       // اترك Laravel يتصرف
        }

        $errorId = (string) Str::uuid();
        Log::error('Unhandled API exception', ['error_id' => $errorId, 'exception' => $exception]);

        $response = ['message' => 'حدث خطأ غير متوقع.', 'error_id' => $errorId];

        if (config('app.debug')) {
            $response['exception'] = $exception::class;
            $response['error']     = $exception->getMessage();
            $response['file']      = $exception->getFile();
            $response['line']      = $exception->getLine();
            $response['trace']     = collect($exception->getTrace())->take(10)->all();
        }

        return response()->json($response, 500);
    });
})
```

### الاستثناءات المستثناة ولماذا

| الاستثناء | يتولاه Laravel | الرمز |
| --- | --- | --- |
| `ValidationException` | رسائل الحقول جاهزة ومفهومة | 422 |
| `AuthenticationException` | رسالة المصادقة معيارية | 401 |
| `HttpExceptionInterface` | `abort(403)` و`abort(404)` مقصودة | حسب النداء |
| `HttpResponseException` | استجابة صريحة من الشيفرة | حسب الاستجابة |
| `! expectsJson()` | طلبات غير API | صفحة خطأ عادية |

الباقي — أخطاء البرمجة والأعطال غير المتوقعة — يُوحَّد في استجابة واحدة.

### `error_id` — الفكرة

كل خطأ غير متوقع يحمل UUID يظهر في **الاستجابة وفي السجل معاً**:

```
المستخدم يرى:  { "message": "حدث خطأ غير متوقع.", "error_id": "9f3a...c21" }
السجل يحوي:    [2026-08-02 10:14:22] local.ERROR: Unhandled API exception
                {"error_id":"9f3a...c21","exception":"[object] (RuntimeException...)"}
```

المستخدم يرسل المعرّف، وأنت تبحث عنه مباشرةً:

```powershell
Select-String -Path BackEnd/storage/logs/laravel.log -Pattern "9f3a"
```

بلا تخمين وقت الحادثة أو تصفح آلاف الأسطر.

### `APP_DEBUG` — الفرق

| القيمة | الاستجابة | الاستخدام |
| --- | --- | --- |
| `true` | رسالة عربية + `error_id` + الصنف والملف والسطر و10 إطارات من التتبّع | التطوير |
| `false` | رسالة عربية + `error_id` فقط | **الإنتاج إلزاماً** |

> `APP_DEBUG=true` في الإنتاج يكشف مسارات الخادم وأسماء الأصناف وأجزاء من الشيفرة.
> هذا تسريب معلومات حقيقي.

## أنماط رمي الأخطاء في الشيفرة

### `ValidationException` لأخطاء قواعد العمل

من `Modules/Reports/Repositories/Eloquent/ReportRepository.php`:

```php
if (! $this->access->canManage($user, $report)) {
    throw ValidationException::withMessages(['report' => __('messages.report_forbidden')]);
}

if ($action === 'return' && blank($note)) {
    throw ValidationException::withMessages(['note' => __('messages.validation_required')]);
}
```

> **لماذا 422 لا 403؟** لأن الواجهة تعرض أخطاء التحقق في مكانها المعتاد، فتظهر
> الرسالة بجانب الحقل. اختيار متعمّد لتوحيد تجربة الخطأ.

### `abort()` لأخطاء الصلاحية الصريحة

من `Modules/Drive/Controllers/DriveController.php`:

```php
abort_if($incomingSize > self::MAX_UPLOAD_TOTAL_BYTES, 422, 'الحجم الإجمالي ... يجب ألا يتجاوز 1GB.');
abort_unless($user->primaryRole() === 'database_manager', 403);
abort_unless($this->canAccessDepartment($user, $departmentId), 403);
```

`abort_if` و`abort_unless` أوضح من `if (...) { abort(...); }` وتُستخدم في كل المشروع.

### `RuntimeException` لأعطال البنية

من `app/Services/Documents/DocxTemplateRenderer.php`:

```php
if (! is_file($templatePath)) {
    throw new RuntimeException("Document template not found: {$templatePath}");
}
if ($zip->open($targetPath) !== true) {
    throw new RuntimeException("Unable to open generated DOCX: {$targetPath}");
}
```

يلتقطها المعالج العام ← 500 مع `error_id`. مناسب لأنها أعطال لا يستطيع المستخدم إصلاحها.

### الفشل الصامت للميزات الثانوية

من `Modules/Communications/Services/DocxPdfConverter.php`:

```php
logger()->warning('LibreOffice PDF conversion failed.', [
    'exit_code' => $process->getExitCode(),
    'error' => trim($process->getErrorOutput()),
]);
return null;
```

> **قاعدة المشروع:** فشل ميزة ثانوية لا يُفشل العملية الأساسية.
> فشل تحويل PDF ← ملف Word يبقى متاحاً. توقّف Reverb ← الرسالة تُحفظ بلا بثّ.
> الاستثناء الوحيد: فشل يترك البيانات غير متسقة — هذا يجب أن يُفشل المعاملة كاملة.

## السجلات

### الإعداد — `BackEnd/.env`

```dotenv
LOG_CHANNEL=stack
LOG_STACK=single
LOG_DEPRECATIONS_CHANNEL=null
LOG_LEVEL=debug
```

الوجهة: `BackEnd/storage/logs/laravel.log`.

| المستوى | الاستخدام في الإنتاج |
| --- | --- |
| `debug` | التطوير فقط — يولّد حجماً كبيراً |
| `info` | مقبول |
| `warning` | **الموصى به للإنتاج** |
| `error` | الأخطاء فقط |

> `LOG_STACK=single` يعني ملفاً واحداً ينمو بلا حد. للإنتاج طويل الأمد بدّله إلى
> `daily` فيُنشئ ملفاً يومياً ويحذف القديم تلقائياً.

### دوال التسجيل المستخدمة

```php
Log::error('Unhandled API exception', ['error_id' => $errorId, 'exception' => $exception]);
logger()->warning('LibreOffice PDF conversion failed.', ['exit_code' => ..., 'error' => ...]);
report($exception);   // في SystemController::health() — يسجّل ولا يوقف التنفيذ
```

`report()` مفيد داخل `try/catch` حين تريد الاستمرار مع تسجيل المشكلة —
يستخدمه فحص الصحة عند فشل الكتابة على قرص.

### المتابعة اللحظية

```powershell
cd BackEnd
php artisan pail                        # كل السجلات لحظياً
php artisan pail --filter="error"       # الأخطاء فقط
```

`laravel/pail` مثبّت ضمن حزم التطوير.

## استجابات الخطأ — المرجع الكامل

| الرمز | الشكل | متى |
| --- | --- | --- |
| 401 | `{"message": "انتهت الجلسة أو لا تملك صلاحية الوصول."}` | توكن مفقود أو غير صالح أو حساب معطّل |
| 403 | `{"message": "..."}` | صلاحية ناقصة أو `abort_unless` |
| 404 | `{"message": "..."}` | Route Model Binding فشل |
| 413 | — | الحمولة أكبر من حد PHP |
| 422 | `{"message": "...", "errors": {"field": ["..."]}}` | فشل التحقق أو قاعدة عمل |
| 500 | `{"message": "حدث خطأ غير متوقع.", "error_id": "..."}` | خطأ غير متوقع |
| 503 | `{"status": "unavailable", ...}` | قاعدة البيانات أو التخزين غير متاح |

## جانب الواجهة

`FrontEnd/src/Api/http.js`:

```js
const data = await response.json().catch(() => ({}));
if (response.status === 413) throw new Error(tr('api_payloadTooLarge'));
if (!response.ok) throw new Error(data.message || fallbackMessage());
return data;
```

| السلوك | التفصيل |
| --- | --- |
| `.catch(() => ({}))` | استجابة غير JSON لا تُسقط التطبيق |
| 413 خاصة | لأن الخادم قد لا يرجع JSON عند تجاوز حد PHP |
| `data.message` | الرسالة العربية من الخادم تصل للمستخدم كما هي |
| احتياطي | `tr('api_requestFailed')` عند غياب الرسالة |

رسائل الشبكة والمهلة مترجمة في `FrontEnd/src/i18n/parts/api.js`:
`api_timeout`, `api_requestFailed`, `api_payloadTooLarge`, `api_uploadTimeout`,
`api_archiveTimeout`, `api_blobFailed` وغيرها.

العرض للمستخدم عبر `FrontEnd/src/Components/Feedback.jsx`.

## قائمة تشخيص سريعة

| العَرَض | الفحص الأول |
| --- | --- |
| 401 على كل الطلبات | التوكن في `localStorage.cnd_token`؟ الحساب `is_active`؟ |
| 403 على مسار واحد | هل الصلاحية ممنوحة للدور؟ هل مُسح كاش الصلاحيات؟ |
| 422 غير مفهوم | افحص `errors` في الاستجابة — يحدد الحقل بدقة |
| 500 مع `error_id` | ابحث عن المعرّف في `storage/logs/laravel.log` |
| 503 عند الإقلاع | قاعدة البيانات متوقفة أو التخزين غير قابل للكتابة |
| رسالة بلغة خاطئة | ترويسة `X-Language` — افحص `localStorage.LANGUAGE` |
| لا شيء في السجل | `LOG_LEVEL` أعلى من مستوى الرسالة، أو مجلد `logs` غير قابل للكتابة |
