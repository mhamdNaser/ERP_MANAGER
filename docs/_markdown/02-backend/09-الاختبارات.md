## الإطار

| العنصر | التفصيل |
| --- | --- |
| الإطار | Pest 3.8 (`pestphp/pest`) |
| إضافة Laravel | `pestphp/pest-plugin-laravel` — تتيح `getJson`, `postJson`, `withToken` |
| الإعداد | `BackEnd/phpunit.xml` |
| التهيئة | `BackEnd/tests/Pest.php` |
| الصنف الأساسي | `BackEnd/tests/TestCase.php` |

## بيئة الاختبار — `phpunit.xml`

```xml
<env name="APP_ENV" value="testing"/>
<env name="DB_CONNECTION" value="sqlite"/>
<env name="DB_DATABASE" value=":memory:"/>
<env name="BCRYPT_ROUNDS" value="4"/>
<env name="BROADCAST_CONNECTION" value="null"/>
<env name="CACHE_STORE" value="array"/>
<env name="QUEUE_CONNECTION" value="sync"/>
<env name="SESSION_DRIVER" value="array"/>
```

| الإعداد | السبب |
| --- | --- |
| `sqlite` في الذاكرة | سريع، ولا يمسّ قاعدة التطوير |
| `BCRYPT_ROUNDS=4` | تشفير كلمات المرور أسرع بكثير |
| `BROADCAST_CONNECTION=null` | لا حاجة لتشغيل Reverb أثناء الاختبار |
| `CACHE_STORE=array` | الكاش في الذاكرة، ينظّف نفسه بين الاختبارات |
| `QUEUE_CONNECTION=sync` | المهام تُنفَّذ فوراً |

> **انتبه:** الاختبارات تعمل على SQLite بينما الإنتاج PostgreSQL. أنواع البيانات
> والدوال الخاصة بـPostgreSQL (مثل `ILIKE` أو `jsonb`) قد تعمل هنا وتفشل هناك، والعكس.
> تجنّب SQL خاماً خاصاً بمحرّك معيّن.

## أنماط الكتابة في هذا المشروع

### المصادقة بالتوكن

المشروع لا يستخدم `actingAs()` لأن المصادقة توكن مخصص:

```php
$manager = User::create([
    'name' => 'مدير البيانات',
    'email' => 'db@test.local',
    'password' => 'password',
    'role' => 'database_manager',
    'api_token' => hash('sha256', 'test-token'),      // ★ الهاش لا الخام
]);
$manager->assignRole('database_manager');

$this->withToken('test-token')->getJson('/api/reports')->assertOk();
```

> **النقطة الأهم:** تحفظ `hash('sha256', 'test-token')` في قاعدة البيانات وترسل
> `'test-token'` الخام في `withToken()`. عكسها يعطي 401 دائماً.

### تحضير الأدوار

```php
$this->seed(RolePermissionSeeder::class);
```

إلزامي قبل `assignRole()` — الأدوار والصلاحيات لا توجد بلا بذور.

### تزييف التخزين

```php
Storage::fake('local');
Storage::fake('public');
```

يمنع كتابة ملفات حقيقية. **إلزامي** في أي اختبار يلمس الرفع أو النسخ الاحتياطي أو الوثائق.

### التوكيدات المستخدمة

```php
->assertOk()                                        // 200
->assertCreated()                                   // 201
->assertUnprocessable()                             // 422
->assertJsonPath('status', 'ready')                 // قيمة في مسار
->assertJsonCount(6, 'analytics.report_trend')      // عدد عناصر
->assertJsonFragment(['kind' => 'internal'])        // وجود جزء
->assertJsonStructure(['analytics' => [...]])       // بنية الاستجابة
```

## كتابة اختبار جديد

مثال كامل — نطاق التقارير لرئيس القسم:

```php
<?php

use App\Models\Branch;
use App\Models\Department;
use App\Models\Report;
use App\Models\User;
use Database\Seeders\RolePermissionSeeder;
use Illuminate\Foundation\Testing\RefreshDatabase;

uses(RefreshDatabase::class);

it('shows a department head only reports awaiting their review', function () {
    $this->seed(RolePermissionSeeder::class);

    $branch = Branch::create(['name' => 'فرع', 'code' => 'BR1']);
    $department = Department::create(['name' => 'قسم', 'code' => 'DP1', 'branch_id' => $branch->id]);
    $otherDepartment = Department::create(['name' => 'قسم آخر', 'code' => 'DP2', 'branch_id' => $branch->id]);

    $employee = User::create([
        'name' => 'موظف', 'email' => 'e@test.local', 'password' => 'password',
        'role' => 'employee', 'branch_id' => $branch->id, 'department_id' => $department->id,
    ]);

    $head = User::create([
        'name' => 'رئيس', 'email' => 'h@test.local', 'password' => 'password',
        'role' => 'department_head', 'branch_id' => $branch->id, 'department_id' => $department->id,
        'api_token' => hash('sha256', 'head-token'),
    ]);
    $head->assignRole('department_head');

    $base = [
        'employee_id' => $employee->id, 'branch_id' => $branch->id,
        'type' => 'daily_report', 'period_start' => now(), 'summary' => 'ملخص',
    ];

    Report::create($base + ['department_id' => $department->id,      'title' => 'ينتظرني',  'status' => 'department_review']);
    Report::create($base + ['department_id' => $department->id,      'title' => 'مسودة',    'status' => 'draft']);
    Report::create($base + ['department_id' => $otherDepartment->id, 'title' => 'قسم آخر',  'status' => 'department_review']);

    $this->withToken('head-token')->getJson('/api/reports')
        ->assertOk()
        ->assertJsonCount(1)
        ->assertJsonFragment(['title' => 'ينتظرني']);
});
```

هذا الاختبار يوثّق قاعدة عمل حقيقية: رئيس القسم يرى ما ينتظر مراجعته **في قسمه فقط**.

## ما يستحق التغطية أولاً

الاختبارات الحالية تغطي جزءاً من النظام. المناطق الأعلى خطراً وغير المغطاة:

| المنطقة | لماذا حرجة | الملف المستهدف |
| --- | --- | --- |
| انتقالات التقارير لكل دور | 5 حالات × 6 أدوار — أعقد منطق في المشروع | `ReportRepository::ensureAllowedTransition()` |
| نطاق Drive والمشاركة | تسريب ملف بين الأقسام مخاطرة حقيقية | `DriveController` |
| مسار اعتماد HR | خصم الرصيد وتوليد الوثيقة | `HrWorkflowService::approve()` |
| رؤية المراسلات الرسمية | 234 سطراً من منطق الرؤية | `FormalVisibilityService` |
| حصص التخزين | تجاوز الحصة يملأ القرص | `DriveController::ensureQuotaAllowsUpload()` |
| رؤية الفورمات | الجمهور والنطاق والفترة | `CustomFormService::publicationVisibleTo()` |

## قواعد

| القاعدة | السبب |
| --- | --- |
| `uses(RefreshDatabase::class)` في كل ملف | معطّل عالمياً في `Pest.php` |
| `Storage::fake()` قبل أي ملف | يمنع تلويث القرص |
| `$this->seed(RolePermissionSeeder::class)` قبل `assignRole()` | الأدوار غير موجودة بلا بذور |
| احفظ الهاش وأرسل الخام | وإلا 401 دائماً |
| اسم الاختبار جملة تصف السلوك | الاختبار توثيق تنفيذي |
| اختبر النطاق بحالة سلبية | "لا يرى تقارير القسم الآخر" أهم من "يرى تقاريره" |
| تجنّب SQL خاصاً بمحرّك | الاختبار SQLite والإنتاج PostgreSQL |
