## الجديد في 1.0.0

### 1. فرع الآليات (Fleet)

وحدة كاملة جديدة. بدأت بمهمة العمل المنقولة من الموارد البشرية، وبنيتها مفتوحة
لما يُضاف إلى الفرع لاحقاً من أنواع طلبات.

```
BackEnd/app/Modules/Fleet/
├── Routes/api.php
├── Controllers/FleetMissionController.php       (138 سطراً)
├── Requests/StoreFleetMissionRequest.php
├── Repositories/
│   ├── Interfaces/FleetRepositoryInterface.php
│   └── Eloquent/FleetRepository.php             (120 سطراً)
├── Providers/FleetServiceProvider.php
└── Services/
    ├── FleetAccessService.php                   (64 سطراً)   النطاق والصلاحية
    ├── FleetWorkflowService.php                 (136 سطراً)  مسار الاعتماد
    └── FleetDocumentService.php                 (152 سطراً)  وثيقة الاعتماد

BackEnd/app/Models/FleetMission.php  ·  FleetMissionAction.php
FrontEnd/src/Page/Fleet/                          (209 أسطر + 3 مكوّنات)
FrontEnd/src/i18n/parts/fleet.js
```

مسار الاعتماد مرحلتان: **الموظف ← فرع الآليات ← المدير العام**. الوثيقة الموقّعة
تُولَّد عند الاعتماد النهائي فقط. الاطّلاع على المهمة حكرٌ على صاحبها وفرع الآليات
والمدير العام — لا يراها رؤساء الأقسام.

التفاصيل الكاملة: [05-modules/14-فرع-الآليات.md](../05-modules/14-فرع-الآليات.md).

### 2. نقل مهمة العمل من الموارد البشرية

`mission` لم تعد نوعاً من أنواع `HrRequest`:

```php
// قبل
public const TYPES = ['leave', 'departure', 'mission', 'document'];
// بعد
public const TYPES = ['leave', 'departure', 'document'];
```

الطلبات القائمة **تنتقل مع بياناتها وسجل قراراتها** إلى جداول الآليات عبر ترحيل
مخصّص، ويبقى الرقم المرجعي كما صدر كي تبقى الوثائق المطبوعة مطابقةً لسجلها.
حُذف معها حقل `destination` من طلبات الموارد البشرية ووثيقتها وواجهتها.

### 3. نظام إدارة الإصدارات

`scripts/version.ps1` + `VERSION` + `CHANGELOG.md`. يحفظ كل إصدار كوسم Git مع نسخة
من قاعدة البيانات، ويستعيد أي إصدار سابق بالكود والقاعدة معاً، بوسم أمان ونسخة قاعدة
قبل كل استعادة. الدليل: [07-guides/04-إدارة-الإصدارات.md](../07-guides/04-إدارة-الإصدارات.md).

## تغييرات قاعدة البيانات

ترحيلان جديدان، وتشغيلهما بهذا الترتيب **إلزامي**:

### `2026_09_20_000001_create_fleet_module.php`

ينشئ جدولين ويسجّل أربع صلاحيات.

**`fleet_missions`**

| العمود | النوع | ملاحظة |
| --- | --- | --- |
| `id` | bigint | |
| `reference_code` | string **فريد** | الرقم المرجعي المطبوع على الوثيقة |
| `user_id` | FK → `users` | صاحب المهمة · `cascadeOnDelete` |
| `created_by_id` | FK → `users` nullable | من سجّلها (قد يسجّلها موظف الآليات نيابةً) |
| `type` | string **مفهرس** | `mission` — مفتوح لأنواع الفرع لاحقاً |
| `start_date` · `end_date` | date | |
| `days` | decimal(5,1) | |
| `destination` | string | الجهة المقصودة |
| `reason` | text | |
| `status` | string **مفهرس** | `pending_fleet` · `pending_gm` · `approved` · `rejected` · `cancelled` |
| `stage` | string **مفهرس** | `fleet` · `gm` · `done` |
| `attachment_path` · `attachment_name` | string | المرفق |
| `decided_at` | timestamp | |
| `document_number` · `qr_payload` | string/text | بيانات الوثيقة |
| `word_path` · `pdf_path` | string | الوثيقة المولَّدة |

**`fleet_mission_actions`** — سجل القرارات: `fleet_mission_id` (FK · `cascadeOnDelete`)،
`actor_id` (FK → `users` · `nullOnDelete`)، `stage`، `action` (`submit` · `approve` ·
`reject` · `cancel`)، `note`.

**الصلاحيات المُنشأة**

| الصلاحية | تُمنح لـ |
| --- | --- |
| `fleet.view` | `general_manager` عبر الدور؛ ومنتسبو الفرع مباشرةً |
| `fleet.manage` | منتسبو الفرع مباشرةً (لا عبر دور) |
| `fleet.approve` | منتسبو الفرع مباشرةً |
| `fleet.request` | كل الأدوار التي تقدّم طلبات |

> منح `fleet.manage` و`fleet.approve` للأشخاص لا للأدوار **مقصود**، كما في الموارد
> البشرية: العضوية في الفرع شخصية لا وظيفية.

### `2026_09_20_000002_move_hr_missions_to_fleet.php`

ينقل البيانات داخل معاملة واحدة:

```
hr_requests (type = mission)  ──►  fleet_missions
hr_request_actions المرتبطة   ──►  fleet_mission_actions
ثم تُحذف الطلبات المنقولة من hr_requests
```

ترجمة المراحل والحالات أثناء النقل:

| في الموارد البشرية | في الآليات |
| --- | --- |
| `stage` = `head` أو `hr` | `fleet` |
| `status` = `pending_head` أو `pending_hr` | `pending_fleet` |
| `gm` · `done` · باقي الحالات | كما هي |

للترحيل `down()` يعيد البيانات إلى `hr_requests` بالترجمة العكسية — أي أن التراجع
عن هذا الترحيل لا يفقد شيئاً.

## التثبيت / الترقية إلى هذا الإصدار

```powershell
git fetch --tags
git checkout v1.0.0        # أو: .\scripts\version.ps1 restore 1.0.0

cd BackEnd
composer install
php artisan migrate         # ينفّذ ترحيلَي الآليات
php artisan optimize:clear

cd ..\FrontEnd
npm install
npm run build
```

> **قبل `php artisan migrate` على بيانات حقيقية:** خذ نسخة —
> `.\scripts\version.ps1 snapshot`. الترحيل الثاني ينقل بيانات ويحذف صفوفاً من
> `hr_requests`، ولا رجعة عنه إلا بـ `migrate:rollback` أو باستعادة النسخة.

### بيانات تجريبية (بيئة التطوير فقط)

```powershell
php artisan db:seed --class=FleetSeeder
```

ينشئ قسم `FLEET` («فرع الآليات») ومستخدمَين: `fleet@cnd.local` (رئيس الفرع)
و`fleet.officer@cnd.local` (موظف آليات)، ومهمة في مسار الاعتماد.

> لا تشغّل البذور على بيئة الإنتاج.

## نقاط معروفة في هذا الإصدار

| الموضوع | التفصيل |
| --- | --- |
| **قالب وثيقة الآليات غير موجود** | `config/document_templates.php` يشير إلى `resources/templates/documents/fleet/mission-approval.docx` وهو غير مُنشأ بعد. `FleetDocumentService::template()` يتراجع تلقائياً إلى قالب طلبات الموارد البشرية، وإن غاب الاثنان لا تُولَّد وثيقة وتمرّ العملية بلا خطأ. ضع القالب الخاص بالفرع حين يصدر. |
| **الترحيلان غير مُنفَّذين على قاعدة التطوير المحلية** | وقت إعداد هذا الإصدار كانت القاعدة المحلية على 65 ترحيلاً — أي قبل ترحيلَي الآليات. نفّذ `php artisan migrate` قبل تجربة الوحدة. |
| **نسخة القاعدة محلية** | `.versions/` مُستثنى من Git. الإصدار المسحوب من GitHub يأتي بلا نسخة قاعدة، فاستعادته تعيد الكود وحده. انسخ المجلد يدوياً إن أردت نقل الإصدار كاملاً بين جهازين. |

## التراجع عن هذا الإصدار

```powershell
.\scripts\version.ps1 list
.\scripts\version.ps1 restore <الإصدار السابق>
```

وإن لم يكن هناك إصدار سابق موسوم (1.0.0 هو الأول)، فالتراجع يكون عن الترحيلين فقط:

```powershell
cd BackEnd
php artisan migrate:rollback --step=2
```

`down()` في الترحيل الثاني يعيد مهام العمل إلى `hr_requests` بمراحلها المترجمة،
و`down()` في الأول يُسقط جدولي الآليات ويحذف صلاحياتها الأربع. بعدها أعد كود
الواجهة والباك إلى ما قبل الإصدار، ثم `php artisan optimize:clear`.

التفاصيل الكاملة لآلية الاستعادة: [07-guides/04-إدارة-الإصدارات.md](../07-guides/04-إدارة-الإصدارات.md).
