## ما الجديد

### 1. تبويب «قوالب الوثائق»

وحدة `Templates` وشاشةٌ لمن يملك `templates.manage` — يملكها مدير قواعد البيانات.

كل قالب Word يبني منه النظام وثيقةً رسمية صار مُدارَاً من الواجهة: يُستبدل بملف
جديد يحلّ مكانه **بالمسار والاسم نفسيهما**، فلا تحتاج الإعدادات تعديلاً. والنسخة
السابقة تُحفظ قبل كل استبدال، فالعودة عنها ضغطة.

أحد عشر قالباً في ست مجموعات: المراسلات الرسمية، الموارد البشرية، فرع الآليات،
الرسائل الداخلية، التقارير، الفورمات.

ما تعرضه البطاقة لكل قالب:

| المعلومة | مصدرها |
| --- | --- |
| موجود / غير موجود، الحجم، آخر تحديث | الملف على القرص |
| الحقول التي تملؤها الوثيقة | كتالوج `TemplateRegistry` |
| الحقول الموجودة فعلاً في الملف | قراءة `word/*.xml` داخل الـdocx |
| الحقول الناقصة | الفرق بينهما — بالأحمر |

**قالبٌ ناقص الحقول يُرفض أولاً** برمز 422 وقائمة بما ينقصه، ثم يُقبل إن أصرّ
من يرفعه. الرفض لا يلمس الملف القائم.

التفاصيل: [05-modules/15-قوالب-الوثائق.md](../05-modules/15-قوالب-الوثائق.md).

### 2. نموذجا الإجازة الرسميان

النموذجان الورقيان المعتمدان في القسم صارا قالبين تُملأ حقولهما آلياً:

| نوع الطلب | القالب | الحقول |
| --- | --- | --- |
| `leave` — إجازة إدارية | `hr/leave-request.docx` | الاسم · المسمى · الرقم الذاتي · المدة · السبب · تاريخا البدء والانتهاء |
| `departure` — إجازة ساعية | `hr/hourly-leave-request.docx` | الاسم · المسمى · الرقم الذاتي · ساعتا البدء والانتهاء · تاريخ اليوم |
| غيرهما | `hr/request-approval.docx` | كتاب الاعتماد العام كما كان |

عند الاعتماد النهائي يختار `HrDocumentService` النموذج بحسب نوع الطلب، ويعود إلى
الكتاب العام إن غاب النموذج الخاص — فلا يتعطّل اعتماد لأن ملفاً لم يُرفع.

**الأصل الورقي الفارغ محفوظ** في `hr/blank/` وقابل للتنزيل من التبويب بزر
«النسخة الفارغة»، لمن أراد طباعته وتعبئته بالقلم.

> النموذجان الأصليان خطوطٌ منقّطة بلا حقول. `scripts/build-hr-templates.py` هو ما
> حوّلهما: يستبدل كل خط منقّط بحقل `{{...}}` ويحتفظ بالأصل. أعد تشغيله إن صدر
> نموذج ورقي جديد، أو ارفع القالب المعدّل يدوياً من التبويب.

## تغييرات قاعدة البيانات

ترحيل واحد: `2026_09_22_000001_add_document_templates_permission.php`

ينشئ صلاحية `templates.manage` ويمنحها لدور `database_manager`. لا جداول جديدة
ولا أعمدة — القوالب ملفات على القرص لا صفوف.

`down()` يحذف الصلاحية.

## ملفات وإعدادات جديدة

```
BackEnd/config/document_templates.php
├── hr.leave_request              ← جديد
├── hr.hourly_leave_request       ← جديد
└── backups_path                  ← جديد، قابل للضبط بـ DOCUMENT_TEMPLATE_BACKUPS

BackEnd/resources/templates/documents/hr/
├── leave-request.docx            ← جديد
├── hourly-leave-request.docx     ← جديد
└── blank/                        ← جديد: الأصلان الفارغان

BackEnd/resources/templates/backups/<المجموعة>/<الاسم>/   ← النسخ السابقة
```

`backups_path` قابل للضبط كي تعمل الاختبارات على مجلد مؤقت بدل الكتابة فوق قوالب
المؤسسة.

## الترقية

```powershell
git fetch --tags
git checkout v1.1.0        # أو: .\scripts\version.ps1 restore 1.1.0

cd BackEnd
composer install
php artisan migrate         # صلاحية templates.manage
php artisan optimize:clear  # الإعدادات تغيّرت — مسح الكاش لازم

cd ..\FrontEnd
npm install
npm run build
```

> `php artisan optimize:clear` ليس اختيارياً هنا: مسارات القوالب الجديدة في
> `config/document_templates.php`، وكاش الإعدادات القديم لا يعرفها.

## نقاط معروفة

| الموضوع | التفصيل |
| --- | --- |
| **حقل البديل في نموذج الإجازة** | سطر «تم اعتماد ... كبديل» بقي خطاً منقّطاً يُملأ بالقلم، لأن لا حقل مقابلاً له في `hr_requests`. إضافته تحتاج عموداً في الجدول وحقلاً في نموذج الطلب. |
| **الأسماء المطبوعة في النموذجين** | اسما رئيس القسم ومدير الإدارة مطبوعان في الأصل الورقي كما ورد. إن تغيّرا، عدّل ملف Word وارفعه من التبويب. |
| **`fleet.mission_approval` غير موجود** | كما في 1.0.0 — لا قالب خاصاً بالآليات بعد، والتوليد يعود إلى كتاب الموارد البشرية. صار رفعه ممكناً من التبويب. |
| **اختباران فاشلان سابقان** | `OrganizationWorkflowTest` — مراسلات الموظفين مع المدير العام، ومجلدات الدرايف لمدير قواعد البيانات. فاشلان قبل هذا الإصدار ولا صلة لهما به. |

## التراجع عن هذا الإصدار

```powershell
.\scripts\version.ps1 restore 1.0.0
```

أو التراجع عن الترحيل وحده:

```powershell
cd BackEnd
php artisan migrate:rollback --step=1
```

> **انتبه:** ملفات القوالب مُتتبَّعة في Git، فاستعادة إصدار سابق تُرجع كل قالب إلى
> محتواه وقتها — بما في ذلك قالب رفعتَه من التبويب بعد ذلك الإصدار. النسخ السابقة
> في `resources/templates/backups/` لا تُحذف (غير متتبَّعة)، فتبقى متاحة للاستعادة.
> للعودة عن قالب واحد استعمل «النسخ السابقة» في التبويب — أدقّ من استعادة إصدار كامل.
