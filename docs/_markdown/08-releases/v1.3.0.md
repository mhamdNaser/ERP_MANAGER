## ما الجديد

مخطط من ثلاث طبقات أعلى صفحة **الشجرة التنظيمية**: الإدارة في القمة، تحتها
الأفرع، وتحت كل فرع أقسامه. يتحدّث تلقائياً مع كل إضافة فرع أو قسم، ومع كل نقل
قسم بالسحب والإفلات — لأنه يقرأ الحالة نفسها التي تقرؤها لوحات السحب أسفله.

الأقسام التي بلا فرع تقف **صفّاً مع الأفرع** تحت الإدارة مباشرةً، لا تحت فرع
وهمي — مطابقةً لما يقوله النظام عنها: «تابع للإدارة مباشرة».

### منع التداخل

التخطيط يمنع التقاطع **بالبناء لا بالتصحيح بعده**:

```
عرض العقدة = max(عرض عقدة واحدة، مجموع أعراض أبنائها + الفواصل بينهم)
موضع الأب  = منتصف مدى أبنائه
```

فلا يتقاطع فرعان مهما كثرت أقسامهما، ولا يحتاج الأمر خوارزمية دفعٍ تصحّح بعد
الرسم. تحقّقت منه عددياً على ست حالات — منها ستة أفرع في كلٍّ خمسة أقسام،
وفرعٌ واحد بعشرين قسماً — فلا تداخل ولا فاصل أضيق من المسموح ولا أبٌ خارج
منتصف أبنائه ولا عقدة خارج اللوحة.

المخطط يُمرَّر أفقياً حين يتجاوز عرض الشاشة (ستة أفرع × خمسة أقسام = 5594 بكسل)
بدل أن يُضغط فيتشابك.

### كيف رُسم

الخطوط في طبقة SVG والعقد عناصر HTML فوقها. السبب: نصّ SVG لا يقتطع تلقائياً
ولا يرث ثيم التطبيق، والاسم العربي الطويل كان سيتجاوز حدود العقدة. بهذا التقسيم
تبقى الخطوط دقيقة والنص على سجيّته.

```
FrontEnd/src/Page/OrgTree/components/orgChartLayout.js   ★ الخوارزمية — بلا React
FrontEnd/src/Page/OrgTree/components/OrgChart.jsx        ★ الرسم
```

فصل الخوارزمية عن المكوّن مقصود: تُختبر بـNode وحده بلا متصفح ولا DOM.
